# Q1

O NONCE serve para garantir que a chave gerada pelo algoritmo é sempre diferente, mesmo que se use a mesma password/chave principal. Tendo um NONCE fixo com a mesma chave, a cifra ChaCha20 vai gerar exatamente a mesma sequência de bytes pseudo-aleatórios. Se um atacante intercetar dois criptogramas cifrados com a mesma keystream, ele pode fazer um XOR entre eles (como visto na ficha anterior) e anular a chave, revelando a combinação das mensagens originais. Isto destrói completamente a confidencialidade da cifra.

# Q2

Afeta exatamente 1 bit. A cifra ChaCha20 é uma cifra sequencial, o que significa que o texto cifrado é gerado através de uma operação XOR bit a bit (ou byte a byte) entre o texto-limpo e a keystream. Como não há mistura ou permutação de blocos (não há difusão ), a alteração de um bit na entrada reflete-se na alteração de apenas esse mesmo bit na saída.

# Q3

- CTR: Igual ao ChaCha20. Alterar 1 bit no criptograma afeta apenas esse mesmo 1 bit na mensagem original.

- CBC: Devido à forma como os blocos estão encadeados, alterar 1 bit no criptograma destrói completamente o bloco atual (os 16 bytes) e altera exatamente o bit correspondente no bloco seguinte.

# Q4

- AES-CTR: A palavra original será substituída pela nova palavra sem corromper o resto do ficheiro sendo, assim, um ataque bem sucedido.

- AES-CBC: O ataque vai falhar no seu propósito principal. Ao manipular os bytes para inserir a nova palavra, o bloco onde a alteração ocorre ficará corrompido após a decifragem. O atacante conseguirá, no entanto, alterar bits específicos no bloco seguinte.

# Q5

Sim, são ambos estritamente necessários, pois resolvem problemas diferentes:

- O salt impede ataques de pré-computação contra as passwords, garantindo que, mesmo que duas pessoas escolham a password "123456", as chaves criptográficas geradas pela KDF serão completamente diferentes porque os salts são aleatórios.

- O NONCE garante que, mesmo que o utilizador cifre a mesma mensagem duas vezes seguidas (gerando a mesma chave derivada, porque usou a mesma password), o criptograma resultante será diferente a cada vez.
